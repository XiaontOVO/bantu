> 更新：2026-10-05。合并本地启停、排障、体验账号、邀请测试部署与移动验收。这里维护操作步骤；用户行为见[产品规格](产品与交互规格.md)，权限与接口见[工程契约](工程设计与接口契约.md)。

## 本地启动与数据

需要 Node.js 22 或更新版本。在 Windows 双击根目录 `启动伴途.cmd`，首次会安装依赖并构建，浏览器访问 `http://127.0.0.1:8787/`。停止用 `停止伴途.cmd`，查看进程、端口与健康检查用 `诊断伴途.cmd`。桌面快捷方式可用对应安装/卸载脚本管理，英文启停脚本是兼容入口。

启动器核对受管进程归属和构建指纹，旧构建确认属于本项目才重启；默认保留 `data/bantu-state.sqlite`。`data/` 还可能含模型配置和进程记录，不删除整个目录做排障。PWA 只缓存界面外壳，本地 Node 服务仍须运行。

```powershell
npm install
npm run check
npm run smoke
npm run recovery
python -X utf8 scripts/check_planning.py
npm start
```

其中 `check` 做类型及自动化测试，`smoke` 做服务和页面健康检查，`recovery` 验证隔离旅行对象的序列化恢复；它不验证正式SQLite备份。构建后另运行 `node scripts/verify-sqlite-recovery.mjs`：只读打开本机库，备份及恢复到 `data/backups/sqlite-recovery-*` 的独立文件，检查全部值、完整性与恢复服务启动，不替换正式库。备份包含私人数据，留在被Git忽略的data目录；证明仅记录数量和结果。文档检查不验证运行。隔离 GUI 脚本使用内存存储，完整入口与现有证据见[验收记录](产品体验全盘核查.md)。

## 地图与定位排障

在“行程 → 地图与路线”用定位按钮重新获取当前位置，最多等待15秒。蓝点及误差圈来自设备，不是计划城市；误差超过200米、位置过期或拒绝授权时不能作为路线起点，可在地图上手动选择实际入口。首页随行、路线页及出发共用前台监听；切到后台暂停，回前台重新获取新坐标。地址查询失败仍能显示有效坐标。手机须使用可信HTTPS并允许精确定位，局域网HTTP不具备同等定位条件；设备粗定位应按提示处理，不能用固定坐标掩盖。

当前配置为真实高德道路服务。无完整轨迹、端点离可用道路过远或服务故障时，显示重试／待估，不画直线道路；单次前端查询25秒上限，支持取消。全程按各站交通方式规划。构建后可运行node scripts/verify-map-routing-lifecycle-ui.mjs，在独立内存服务验证手机触摸、坐标系、晚回执、定位与网络超时及首页／路线页视角。GPS和道路夹具只证明客户端交互；真实供应商证据另见tmp/map-route-real-road-proof.json，现场GPS仍须手机实测。此次修复不会开放局域网或外网服务。

## Android 测试版安装与服务接入

[下载本地 Android 测试版 APK](../submission/伴途-Android测试版.apk)。2026-10-05 已完成测试包构建、签名并安装到项目专用 `Bantu_Test` 模拟器（`emulator-5560`）；这说明安装包可安装，不代表全部功能或真机已经验收。当前包为 `0.1.0-test`，应用标识 `cn.bantu.travel`，最低 Android 8.0／API 26，目标 API 35，使用测试签名，不是应用商店发行包。

1. 将 APK 传到手机并安装。Android 如提示安装来源权限，按系统提示仅对所用安装来源允许安装；之后可撤回该来源权限。
2. 首次打开看到“连接你的伴途”，填写由服务提供者给出的 HTTPS 地址，如 `https://你的服务域名`，点“连接，开始旅程”。地址只填写协议、域名及可选端口，不带路径、账号、查询参数或邀请码；省略协议时默认 HTTPS。
3. 若服务另设HTTP认证，先输入服务提供者给出的服务用户名/口令，再按网页输入本次邀请码，最后使用自己的游客或账号身份。HTTP认证不代替邀请码或应用账号；APK 不内置邀请码，也不绕过服务端门禁。服务认证仅在当前Activity内存中按同源及认证域临时复用，不写入磁盘，换服务或Activity销毁后清除。
4. 在首页按系统返回键打开退出确认，可选“连接设置”修改服务地址；网络错误页也有“修改服务地址”。切换到不同服务会清除此 App 内的登录及本地缓存，不会删除原服务器上的账号资料。未注册游客切换前应先注册保留资料，之后在原服务重新登录。

App 加载所填服务提供的同源网页和 API，计划、地点、地图、Agent 与私人记忆继续使用现有业务规则。原生层适配返回键、场景横屏、定位授权、系统朗读及文件选择；是否实际可用需要按下面的测试范围核验。系统定位权限与网页功能开关各自生效，拒绝定位仍使用原有的手动入口。朗读依赖设备已安装的 TTS 引擎和中文音色，不等于已提供云端音色。

服务、网络和模型供应商仍须可用。APK 不打包 Node 后台、SQLite、官方或个人模型密钥，也不能在手机离线完成全部功能。当前正式服务只监听 `127.0.0.1:8787`，局域网及外网邀请已关闭；安装或连接 App 不会修改监听、防火墙或启动隧道。手机直接填写电脑的 `127.0.0.1` 无法访问电脑；远程使用须由服务提供者明确开放带邀请验证的可信 HTTPS 入口。App 不接受忽略证书错误或普通局域网 HTTP 作为远程连接方式。

### USB 连接本机测试

仅限本测试包：调试地址 `http://127.0.0.1`、`http://localhost` 及模拟器主机地址 `http://10.0.2.2` 允许 HTTP，其他地址必须 HTTPS。实体 Android 开启开发者选项及 USB 调试、通过数据线连接电脑，并确认本机调试授权。电脑上的伴途先按本地启动步骤运行，再执行：

```powershell
& .\data\android-sdk\platform-tools\adb.exe devices
$bantuDevice = '替换为上面显示的设备序列号'
& .\data\android-sdk\platform-tools\adb.exe -s $bantuDevice install -r .\submission\伴途-Android测试版.apk
& .\data\android-sdk\platform-tools\adb.exe -s $bantuDevice reverse tcp:8787 tcp:8787
```

在 App 中填写 `http://127.0.0.1:8787`。ADB reverse 仅把该设备的指定端口经 USB 转到本机服务，不开放局域网／公网；手机拔线或电脑服务停止后无法继续连接。普通本机服务有回环访问豁免，此步骤本身不能证明外网邀请码拦截；自动 APK 验收使用独立服务并显式关闭回环豁免另测门禁。测试结束移除映射，必要时在手机关闭 USB 调试：

```powershell
& .\data\android-sdk\platform-tools\adb.exe -s $bantuDevice reverse --remove tcp:8787
```

## 在线服务配置

- 无高德 Key 使用本地地点目录；正常服务通过 OSM 道路网估算步行/驾车，不含实时路况。配置高德后使用对应地点和路线能力，支持公交；能力缺失不伪造线路或时间。
- 在根目录 `.env` 设置 `AMAP_API_KEY` 后重启，模板为 `.env.example`。坐标系和道路语义见产品规格，不把隔离路线夹具当在线结果。
- 测试期默认提供「伴途官方」Agent 服务，沿用当前服务器的 API 配置；游客和账号无需填写密钥即可使用。官方配置保存在 `data/model-settings.json`，或由服务器环境变量提供，具体适配见 `src/providers/factory.ts`。仅服务器本机「我的 → 高级信息 → 官方 Agent 服务维护」可修改全站默认服务；邀请入口仍禁止远程维护。
- 用户在「我的 → Agent 服务 → 自行接入」填写自己的 Base URL、模型名及 API Key，需登录或注册账号。选择兼容 Chat Completions 或 Responses 且支持工具调用的公网 HTTPS API；先完成调用工具、回传工具结果的两轮验证，测试成功后才保存启用。接入仅对当前账号生效，可切回官方并保留自有配置，也可删除自有 API 与密钥。更换地址须重新填写 Key；自有服务失败不会自动改用官方。
- 官方GLM已按用户授权采用开启／较轻；自行接入默认请求关闭。可在「我的 → Agent 服务」保存本人的开关和开启后强度；未指定时继承所用服务设置。官方环境变量为 MODEL_API_FORMAT=chat-completions/responses、MODEL_THINKING=off/on、MODEL_THINKING_EFFORT=low/high、MODEL_THINKING_FORMAT=auto 或供应商实际参数协议，模板见 `.env.example`。本机已保存配置优先于环境变量；个人偏好不修改全站配置。未识别协议不能保证关闭；无关闭能力的模型需换模型，不静默降级。接入层支持兼容工具协议，尚未提供 Anthropic/Gemini 原生协议；具体字段及限制见工程契约。
- 自有密钥独立加密保存在 `data/user-model-settings.json`，加密密钥为同目录 `.json.key` 文件；二者均不进入用户快照、聊天或浏览器存储，也不回显。备份须同时保留密文和加密密钥，并限制备份访问；缺失或损坏不能直接重建覆盖。自有地址每次请求都校验解析结果并固定连接 IP，拒绝内网及保留地址和重定向；连接测试按账号限频。
- 规则处理不能计作真实模型验收；当前照片工具只向模型提供附件元数据，尚未传图片内容，不能宣称已识别照片。连接探针 15 秒，普通请求默认 30 秒；托管输出截断后的受限续试可使用 60 秒，不让探针期限截断正常计划处理。
- 天气来源是预报；未取得数据保持未知。供应商效果、配额、网络和资料可用性均需单独核验。

## 开启智能伴行与统一朗读

在首页点“智能伴行”，或进入“我的 → 通用 → 智能伴行”，开启“智能伴行”并允许浏览器定位。功能默认关闭；“自动朗读介绍”单独控制声音，可关闭自动朗读而保留到场介绍卡。开关按当前身份保存在此设备，不会替其他账号开启。

保持伴途在前台，到已收录地点附近停留约20秒。两次新鲜定位的精度须不差于50米；优先核对当前有效计划站，无计划也能识别最近目录地点，计划外途经地点同样可用。当前位置接近多处建筑且不能明确区分时，等待更准确定位，不推断室内或楼层。当前目录27处均可提供介绍，有场景的地点才显示“进入场景”；到场不会替旅者记录到达／完成，也不会自动跳转页面。

确认候选后显示虚拟形象与准备状态，再调用当前身份选择的官方／自接模型生成短介绍。模型不可用时显示已收录资料及重试提示；自接失败不自动换官方。介绍卡的“朗读介绍”可手动播放、停止；“继续聊聊”打开小聊天窗并携带当前地点，“地点资料”由旅者主动进入。关闭介绍卡停止本次介绍与朗读，仍留意后续地点，原页面继续可用；需要停止监测时关闭“智能伴行”开关。输入、编辑、聊天、设置或场景期间避免主动打断；应用切到后台停止定位与朗读，回到前台重新核对位置。

在智能伴行设置点“音色与声音”，或进入“我的 → 通用 → 参观设置”，选择“伴途共用音色”并试听。智能伴行、Agent回复和场景讲解共用该音色；设备中文语音自动优先普通话，手动选择优先于自动选择。Agent完整页和悬浮窗每条回复均有朗读／停止按钮，长文分句连续播放；简约模式保留播放状态。音色取决于浏览器和系统，并非已接入云端TTS。需要安静参观时，在参观设置开启“安静参观”，抑制主动介绍和声音。

浏览器可能要求先触摸才允许发声。等待状态只代表已提交朗读；实际onstart才显示正在播放。8秒仍未开始，或设备拒绝／失败，会显示可重试提示，可点“朗读介绍”重试；只有排队不算已播放。手机定位需要可信HTTPS，电脑本机127.0.0.1可用于安全上下文测试；局域网HTTP通常不能提供手机定位。当前服务仍仅监听127.0.0.1:8787，局域网与外网邀请入口关闭，新增功能没有自动开放服务。

构建后可运行 `node scripts/verify-smart-companion-ui.mjs`，验证手机触摸、定位时序、账号隔离、共享音色和显示组合；其模型、GPS和语音是夹具，当前431项通过。另运行 `node scripts/verify-smart-companion-live.mjs`，使用已配置官方模型、临时Edge与独立MemoryStateStore完成自动到场介绍及原生朗读观察，当前19项通过、1次真实GLM调用、模型错误0，自动／手动均收到原生onstart，关闭后取消播放。该脚本不改正式配置或用户库，定位与时钟仍受控；报告在tmp/smart-companion-live-proof.json，不能替代实体Android／iOS手机、现场GPS或人耳听感验收。完整实现及证据见[体验核查](产品体验全盘核查.md)。

## 账号与游客保留

“我的”页管理账号、社区昵称及本机配置。账号为 3–24 位英文、数字或下划线，不区分大小写；密码 8–128 位，以加盐摘要保存。当前无密码找回、邮箱验证和第三方登录。

游客注册新账号保留原主体的计划、往日记录、笔记和收藏，更新会话使旧凭证失效。登录已有账号切换数据，不合并游客资料，并撤销原游客会话；登录失败保留原身份。游客会话默认 30 天，清除站点数据、过期或切换后不能承诺自动找回。希望保留游客资料先注册。

退出撤销当前会话，已有账号以后可重新登录。会话失效提示跨页/本标签刷新保留，可关闭或成功登录后收起；过期账号数据仍属原账号，未注册游客不具有账号密码恢复入口。

评论、回复、发帖、地点分享及评价使用账号昵称，表单不再要求另填昵称。游客公开阅读，社区写入需账号。帖子可公开或仅自己可见，已有帖详情修改“可见范围”；私密范围也保护照片、评论及收藏。

## 当前局域网邀请测试

双击根目录 `开放局域网测试.cmd`，等待构建和健康检查完成，窗口会显示当前 Wi-Fi／以太网地址及本次 8 位邀请码。测试者连接同一局域网，用浏览器打开显示的地址（默认端口 8787），输入邀请码后进入伴途；邀请通行与应用账号是两层凭据，每个设备仍有独立游客或账号数据。

每次运行开放入口都会重启已经确认归属本项目的服务，并重新生成邀请码，即使构建没有变化，也不会复用旧码。上一轮邀请码和通行 Cookie 均失效；测试者重新输入本次邀请码即可继续，已有应用账号与资料保留。局域网入口强制随机模式，不受 `.env` 中固定 `BANTU_ACCESS_CODE` 覆盖。普通启动若复用当前进程，则显示当前邀请码，不额外轮换。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-lan-test.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/stop-lan-test.ps1
```

双击 `关闭局域网测试.cmd` 将服务恢复为仅 `127.0.0.1` 监听，本机页面继续可用；`停止伴途.cmd` 停止整个服务。命令行可用 `-Port` 指定端口。当前开放信息保存在被忽略入库的 `data/lan-access.json`、`data/access-code.txt`，只保留最近实例，不通过站点提供；以启动窗口和当前进程为准，不把旧文件当在线证明。默认访问 Cookie 最长 30 天，重新开放会提前作废；本机 `127.0.0.1` 访问免邀请码，模型管理仍只允许本机，邀请码不授予其他账号或审核权限。

此入口直接使用本机 Node 服务，没有公网隧道和对外域名。首次连接受 Windows 防火墙和 Wi-Fi 隔离策略影响：允许 Node 的当前网络入站访问，手机和电脑使用同一网络；无法连通时先核对当前地址、服务监听和网络策略，不关闭整个防火墙。`scripts/start-invite-test.ps1` 是已有的公网隧道试验入口，不用于本节局域网测试。

校园网／访客 Wi-Fi 即使名称相同，也可能禁止设备互相连接。若服务监听与本机访问正常、Node 当前网络入站已放行，而测试设备仍超时，需进一步核对客户端地址和网络策略；这不能靠邀请码修复。现场测试可让电脑和测试设备接入个人热点或独立路由器，再运行局域网开放入口，使用窗口新显示的 IP。

局域网 HTTP 地址在浏览器中通常不是安全上下文，实时定位和 PWA 安装可能不可用。地图、账号、社区、计划及 Agent 可进行网页测试；定位不可用时使用页面现有的明确降级和手动地点能力，不能宣称已验证真实定位导航。需要测试真机 GPS/PWA 时，另用可信 HTTPS 入口。独立设备能否访问仍需在该设备上实测，不能以本机请求成功替代。

## 单实例邀请部署

### 临时外网邀请

校园网内设备无法直连时，双击 `开放外网邀请测试.cmd`。这台电脑继续作为应用服务器，默认通过 Cloudflare Quick Tunnel 将本机邀请网关发布为临时 HTTPS 地址；访客无需同网，输入本次随机 8 位邀请码后使用网页。脚本核对本项目进程归属，必要时启动服务或恢复业务端口为仅 `127.0.0.1` 监听，避免旧局域网邀请码成为另一入口。打开操作会先安全关闭本项目上一轮外网邀请，重建地址和通行凭证；关闭用 `关闭外网邀请测试.cmd`，本机应用继续运行。

脚本先清空上一轮日志，再读取新隧道地址，实际检查公网邀请码页后才报告成功；只有取得域名不算成功。Windows PowerShell 5.1 的 HTTPS 握手可能失败，验证由独立 Node 进程调用系统 `curl.exe` 并读取 UTF-8；隧道使用 HTTP/2，自动选择可用 IP 协议。当前校园网 DNS 实测对部分新域名返回“不存在”，验证会单独查询独立 DNS，并在请求中临时指定解析结果，仍核验真实域名的 HTTPS 证书；不改系统 DNS 或 hosts。若启动窗口提示此情况，测试者先关闭校园 Wi-Fi、用手机流量访问。失败会清理本次启动的网关和隧道，保留本机服务与数据库。进程记录和本次邀请码位于系统临时目录 `bantu-share/processes.json`，不作为永久演示地址。

网关仅监听回环，所有代理页面、接口和素材都需邀请码；未授权接口（包括公网健康检查）返回 `401 ACCESS_CODE_REQUIRED`，未授权页面／素材只返回邀请页，不代理业务内容。错误邀请码不签发 Cookie，反复错码会返回 429；输入接受大小写、空格和连字符。通行 Cookie 每次启动重新生成，并添加 Secure、HttpOnly；最长 24 小时，网关同时检查服务端有效期。重新开放后旧邀请码和旧 Cookie 都失效；已有应用账号凭据也不能绕过邀请码。代理上游固定非本机 Host，外网访客不能因回环代理连接而获得模型设置权限；不能转发客户端伪造的来源 IP。应用账号、私密内容和审核凭证仍由服务端单独校验。本机 `127.0.0.1` 仍用于管理与探活。

2026-09-29 当前隧道已由测试者在手机上确认可输入邀请码并进入首页。`scripts/verify-invite-live.mjs --check-previous` 实际走公网 HTTPS，验证旧码／旧凭证拒绝、未授权 API 与素材拦截、正确码进入、界面脚本加载和远程模型管理拒绝；仅检查门禁与素材，不创建账号或改用户内容。复核记录在系统临时目录 `bantu-share/verification.json`，不含邀请码或 Cookie。`verification-private.json` 仅在本机保存前一次验证凭证供轮换检查，不通过站点提供。自动浏览器复核若启动正常，会产生一个独立游客会话，不登录既有账号或发布内容。

电脑需要保持开机、联网，伴途、网关、隧道持续运行；休眠、关机或关闭隧道后访客无法使用。临时域名和第三方隧道均不保证持续可用，需在测试者实际设备上核验；Quick Tunnel 不支持 SSE，本项目当前聊天使用普通 HTTP 请求。长期远程邀请、稳定演示入口采用下文服务器部署。HTTPS 提供浏览器定位所需安全上下文，但实际定位仍需设备权限和实机验证。脚本另有 `-Transport` 排障选项；目前的成功验收是 Cloudflare 通道，不能将其他通道有命令配置视为可用证明。

### 固定服务器入口

当前部署配置用于小范围邀请测试：单台 Linux 服务器、单个应用容器、持久化 SQLite，Caddy 提供 HTTPS 和站点访问口令。邀请口令与应用账号是两层凭据。仓库有配置不表示已有公开部署。

准备 Docker Engine/Compose、指向服务器的域名、可访问的 80/443 端口及邀请口令。复制模板并配置自己的域名和认证信息：

```sh
cp .env.deploy.example .env.deploy
docker run --rm caddy:2 caddy hash-password --plaintext '替换成邀请口令'
```

把哈希用单引号填入 `BANTU_AUTH_HASH`，设置 `BANTU_DOMAIN` 和 `BANTU_AUTH_USER`；`.env.deploy` 已忽略，不提交真实认证信息。

```sh
docker compose --env-file .env.deploy up -d --build
docker compose --env-file .env.deploy ps
docker compose --env-file .env.deploy logs -f app caddy
```

更新同样执行 `up -d --build`。从独立设备和网络访问自有域名，输入邀请口令，再使用应用账号；核对首页、模型/地图网络、发帖权限和重启数据保留，才将该入口填入赛事 LIVE DEMO。

- 数据、模型配置和错误日志在 `bantu_data` 卷中，备份卷而非仅代码；不得同时由多个实例挂载 SQLite，不做横向扩容。
- `TRUST_PROXY_HOPS=1` 仅适用于应用只由 Compose 内 Caddy 访问；不要再公开应用 8787 端口。
- 帖子图片随状态存 SQLite，适合邀请规模。公开运营或大量用户前需数据库迁移、图片对象存储、跨实例限流和请求来源防护等独立验收。
