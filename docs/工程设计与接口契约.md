# 伴途｜工程设计与接口契约

> 更新：2026-10-05。架构、模型、现有接口、Agent 授权与代码入口的唯一工程文档。当前为 Node HTTP + SQLite 单实例；保留 Trip 兼容域，但新页面无 Trip 前置。业务体验见[产品规格](产品与交互规格.md)，执行详规见[三态规范](计划与进度三态转换逻辑.md)。

## 运行架构

浏览器加载 public/，通过 /api/v1 请求 Node HTTP 服务；路由调用业务服务，服务调用领域规则、供应商与状态存储。默认本地 SQLite，隔离测试内存存储。PWA 缓存应用外壳，不承担完整离线业务执行。

静态资源网络优先；Service Worker 在响应交付前复制成功的响应，通过 waitUntil 后台缓存，缓存打开/写入失败不影响在线响应。网络本身失败才查询该资源的缓存，脚本不得回退为入口 HTML。当前外壳版本 v191，故障回归见 tests/service-worker.test.ts；完整离线业务仍不支持。

启动恢复区分可用界面与完整初始化：`render.js` 在成功渲染后设置 `__bantuUiReady`，`app.js` 完整启动后才设置 `__bantuBooted`；明确错误页设置 `__bantuRecoveryShown`。经典 `boot-recovery.js` 在 6 秒时检查三者，无页面反馈才显示遮罩。10 秒超时由 `startup-recovery.js` 向现有页面插入说明，保留原 DOM，收起提示返回原编辑焦点；导航重绘沿用同一错误状态。初始化按等待后的最新路由继续，成功清除提示，`render.js` 恢复仍存在的输入框焦点和选区。`scripts/verify-startup-navigation-ui.mjs` 通过真实鼠标/键盘、受控慢读取、断网及模块阻断核查；不写现有 SQLite。

### Android 应用与共享前端

`android/` 使用平台 WebView 加载用户设置的伴途服务，包名 `cn.bantu.travel`，最低 API 26，目标 API 35。网页的计划、Agent、社区、场景和数据接口继续由同一套 `public/` 与 Node 服务实现；APK 不内置业务数据库、模型密钥或独立后端。安装与构建方法见[运行与部署](运行与部署.md)。当前产物为测试签名包；Android 8+ 是最低安装要求，实际设备覆盖以验收记录为准。

首次启动配置服务地址，默认 HTTPS。测试构建允许 `127.0.0.1`、`localhost` 与模拟器宿主地址 `10.0.2.2` 的 HTTP，不能将任意局域网 HTTP 当成生产配置。只接受根服务地址，拒绝凭据、路径、查询、片段与无效端口；正常页面只加载同源业务，额外允许 HTTPS 高德瓦片资源。外部网页由系统浏览器处理，SSL 错误不继续加载。正式版不启用 WebView 调试和回环 HTTP 例外。

桥接在 `MainActivity.java`、`public/lib/native-shell.js` 与 `scene-presentation.js`。没有 `BantuNative` 时，浏览器继续使用原有能力；只有缺少网页语音接口时才安装原生语音适配器。`speakSpeech`／`cancelSpeech`／`getSpeechVoices` 使用设备 TTS，真实 `onStart`／`onDone`／`onError` 回到网页，不能把入队当成已经播放；取消和过期回调依照代次与请求 ID 丢弃。全屏请求由 `setSceneFullscreen` 与 `onFullscreenResult` 确认，成功才设置场景全屏状态；导航、后台与失败释放横屏请求。系统返回优先关闭网页弹层、离开场景、关闭小窗、返回首页，首页再交由原生退出提示。

设备位置仅向当前服务源和前台页面提供，系统权限弹窗与 Activity 生命周期必须一起处理；不申请后台定位。文件上传经系统文档选择器返回 URI，不能开放网页对任意本地文件的读取。切换到不同服务源时清理旧 Cookie、DOM 缓存与 Service Worker，并销毁旧 WebView；同源重新连接及普通冷启动保留邀请码、账号与偏好。原生回调核对服务源、WebView 代次和前台状态，不能作用到新页面或其他服务。

服务若配置 HTTP Basic Auth，原生面板接受用户手动输入的服务用户名与密码，随后仍须通过伴途邀请码。凭据仅保存在当前 Activity 内存，并仅复用于同源、同 realm 且 Android 允许重试的挑战；拒绝后清空并重新询问，不使用 WebView 持久密码库。后台取消待处理的认证请求，重新连接或销毁 Activity 清空凭据；APK 中不内置服务密码。

测试入口：`tests/native-shell.test.ts` 覆盖桥接取消、晚回调与浏览器路径；`android/app/src/test/java/cn/bantu/travel/ServerUrlPolicyTest.java` 核对地址与同源规则；`scripts/verify-android-app.mjs` 操作实际 APK 与系统返回；`scripts/verify-half-day-mobile.mjs --apk` 复用原手机半日游断言。后两者使用项目模拟器和内存服务，真实模型与模拟定位／道路／时钟应分别声明，不替代现场真机验收。

## 主要流程

### 半日游接续与任务隔离

personal-agent-tasks 在任务开始时保存 requestText，表示本次实际用户指令；聊天历史保留为对话资料。personal-agent-runtime 仅对 resumed／confirmedTask 使用这条指令恢复原规划目标，新编辑、进度或记忆任务不从旧用户消息恢复创建目标。这样旧创建对话不会排除 plans.adjust_stop 等编辑工具，续办仍使用原任务检查点。

personal-agent-result-links 从成功写入回执读取当前主体拥有的最新对象。日计划返回 view=home、planId 与 date；执行回执也可携带此入口，已生成私人旅程时增加对应 memoryId。agent-result-navigation 读取后核对主体与 navigationRevision，日计划进入首页并设置 companionPlanId，无日期方案保持方案页定位。失败、已删及其他账号对象不生成入口。

首页游览阶段有场景的地点使用同排“进入场景／结束游览”。place-scene 的来源标识包括 planId、revision、stopId 和 phase；取消、导航或当前节点变化后不接纳旧成功或失败。等待与失败在原卡显示，不写进度。journey-review 重新读取记忆，按 sourcePlanId 选择个人 journey，保护主体、导航和重复点击；没有记录时允许原页重试，不编造旅行内容。最后完成时仍由既有业务服务生成真实足迹，用户感受由本人提供。

验证入口：scripts/verify-half-day-journey.mjs 为真实模型与旅行供应商的隔离HTTP流程；scripts/verify-half-day-mobile.mjs 为真实模型、模拟时钟/GPS与道路夹具的触摸流程；scripts/verify-journey-layout.mjs 为真实输出派生的手机布局夹具。tests/frontend-journey-review.test.ts 覆盖准确记录、过期读取和失败重试，tests/frontend-scene-loading.test.ts 覆盖首页计划版本／节点／阶段变化。测试不写用户SQLite，不把模拟定位算为现场验收。

### 方案与日期计划

编辑草稿并保存方案；载入时检查目标日期、已有计划与进度冲突，需要确认则展示具体影响，确认期间内容变化须重新检查。载入生成日计划，源方案独立保留。直接添加地点与创建计划同样经服务写入。

无模型的兼容命令安排在保存／更新后，按本次新增stopId读取已提交日计划的实际归属日期；跨午夜或合并到次日时，回复逐日分组、明确顺延，date选择最早实际归属日。取消与进度仍仅作用于所指定日期，不因安排来源日期不同而修改其他日。固定23:55、等价UTC、00:05及上午的回归见 `tests/standalone-midnight-arrangement.test.ts`。

### 真实进度与路线

出发的前置道路核对失败或缺少有效估时，不直接提交第二次估算。原页面显示取消／重新查询／“我已出发，先记录”；用户明确选择后传skipRouteEstimate，真实出发与未知预计分别保存。路线有效且步行超过90分钟或预计次日凌晨到达时，仍使用既有确认面板。scripts/verify-feedback-1001.mjs 在首页及计划页复验确认前无事实、取消、前置连接失败与明确待估路径。

出发先尝试取得新鲜位置，由服务按所选方式估算道路。定位失败时展示原因、重试与“我已出发，先记录”；明确降级后保存出发事实但跳过估算。计划与进度可打开完整地图，首页随行保持同页展示。首页启动与返回时恢复随行目标并加载只读路线；离开或隐藏首页停止额外定位监听和轮询。

到达、完成、补记与纠正使用执行事件和版本校验。领域层保存事实，读取视图派生预计时段、未知转场与预约冲突。跨日事实留原日，尚未开始且真实顺延至次日的站点才迁移；预测不会写成事实。完整规则见[三态转换](计划与进度三态转换逻辑.md)。

静态多日方案另有跨日分组：开始时间达到 1440 分钟时，将地点及时间别名归入对应天；开始在当日、结束在次日的地点保留完整原节点，补齐后续天并派生只读延续行。24:00 结束按半开区间处理。保存/更新先校验提交引用，再分天并复核单日及跨日冲突；旧方案读取和过期安排转为方案使用相同规则。执行事实仍按日计划 T7/T8 处理。

随行道路及天气查询是只读视图，不推进执行。四类临时变化由确定性服务核对目录、道路、开放时段和保护条件，最多返回三个候选；确认绑定主体、日计划、版本、事实摘要、参数和有效期。确认回执与计划一起持久化，重复请求不二次修改，源方案不被更新。详见[随行规划](产品与交互规格.md)。

### Agent 与权限

消息 → 模型/规则处理 → 参数与权限检查 → 工具调用业务服务 → 返回真实结果 → 同步页面。个人 Agent 无 Trip 前置；旅行兼容提案仍绑定具体旅行、版本、候选和许可。停止只停止后续步骤，不撤销已提交结果。见[授权设计](工程设计与接口契约.md)。

### 地点详情与搜索结果隔离

public/lib/place-detail.js 通过既有 GET /api/v1/places/:placeId 读取当前目标，独立于 loadPlaces 的关键词、筛选及分页。navigate、启动深链接、同页原生 hash 换地点和原位重试共用读取器；openPlacePage 先记录返回来源并导航，不再等待详情后跳转或把详情插入 state.places。重绘共用当前未完成请求，明确重试撤销前次读取。AbortController、请求序号、主体、导航版本、当前页面及地点编号共同保护回执；切页、账号暂停或更换主体失效旧读取。返回后的延迟滚动也须仍属于原返回导航。

api.js 的普通 HTTP 错误保留 status 与 code，消息保持原样。只有 404 + RESOURCE_NOT_FOUND 标为 missing，网络、供应商或其他故障是可重试 error；返回资料须匹配目标，兼容高德原始 POI 编号到 amap_ 前缀的既有别名。详情内存缓存上限 64 条，主体变化清空，不进入浏览器持久存储，也不复制私有备注去覆盖正在编辑的备注状态。findPlace 共用详情缓存、地图、目录、完整目录、收藏与计划快照及已审核推荐的查找链；备注仍由本人备注接口读取。评价及标签写入成功后刷新当前匹配详情，离开后不导航回来源。

首页随行读取复用 cachePlaceDetail，并要求传读取时的主体与匹配地点编号；resolveStopPlace 优先采用本人详情缓存。loadCompanion 的目标详情有独立请求代次和 AbortController，回执核对原主体、导航版本、前台、计划／到访／模式键；不扩充 state.places，也不修改详情页的等待状态。路线读取用 companionQueryStage 表达定位／道路阶段，在请求建好后用微任务刷新反馈；cancelCompanionRoute 撤销当前请求代次、恢复入口及焦点，保留原 context，后一次请求不会被旧成功／错误／finally 清除。watch 权限承诺与回调另核对 trackingGeneration、导航和目标键；清除后迟到回调无效。有效设备位置要求有限经纬度、误差大于0且不超过200米、两分钟内且不超前五秒。前台、离页与账号暂停仍只影响派生视图，不产生执行事实。验收见 tests/frontend-companion-session.test.ts、verify-home-place-layout-ui.mjs 与原随行进度脚本。

确认公开撤回时清除该编号的详情缓存，详情页只可回顾本人收藏或计划中的快照，不能退到旧搜索／地图资料。快照明确标记并关闭加入新计划、场景、评价、标签与备注编辑，已有收藏仍可移除；重新核对公开恢复后取消限制。本轮不新增接口、后台数据库字段或执行事实。隔离内存服务下的深链接、刷新、同页 hash、实际收藏触摸／返回、网络与服务失败、重试、撤回快照和手机布局见 scripts/verify-place-detail-ui.mjs；请求失效、身份隔离与错误分类见 tests/frontend-place-detail.test.ts。

place-tour-data.js 为建筑标注 spaceKind：exterior 只含外观资料，outdoor 是已收录的室外亭廊，unknown 为未核实轮廓；不通过地点分类推断室内可参观。武康大楼移除无依据的 1F 占位，overviewBuildingRecords 的未知轮廓以空 floors 和 floorInventoryKnown:false 返回。place-tour.js 的覆盖数排除上述类型与 area-diagram 功能图，数字只指已收录楼层。点击入口始终保留，按资料性质显示外观、室外、楼层或未知说明；无总览图不生成放大动作。实际楼层选择带分组说明与 aria-pressed，保留所选楼层记忆及原大图返回。外观／室外说明使用静态 note，避开通用 status 警告样式，面板依内容撑高；关闭按钮共用明确的 44px 范围。规则见 tests/frontend-tour-guidance.test.ts，实际触摸与布局见 scripts/verify-tour-guidance-ui.mjs。本轮只改资料表达和交互，不改变原 SVG、地理坐标或新增未经核实的室内资料。

### 智能伴行与共享语音

`smart-companion-preferences.js` 保存主体隔离的enabled／autoplay；`smart-companion.js` 维护独立定位监听、完整分页目录、请求代次、当前计划站次及候选去重。重用scene-arrival.js两次精确定位与20秒停留规则；候选圈100米，原始高德坐标在服务端统一转WGS84。处于范围内的有效当天计划当前站优先，其他已收录地点仍可作为最近候选，相邻候选差距不足定位误差时不触发。GPS不是身份、业务事实或室内位置证明。后台／身份变化立即撤销监听与请求，旧watch、getCurrentPosition、资料及模型回执均按代次失效；取消loading时解除本次去重，使返回后新的稳定定位可重试。

GET候选返回全部公开目录、WGS84坐标／arrival或null、sceneAvailable和资料性质；POST介绍用Cookie主体的modelProviderForActor，只读tools:[]且不写聊天、计划、进度或记忆。客户端提供的资料、位置或主体不作为提示或权限。介绍限定已收录资料，错误主题、工具输出、无依据楼层／实时价格等被拒绝；模型失败返回source=catalog、modelError与原资料，仍可手动重试。独立每主体每分钟12次限流，不消耗普通Agent任务额度；单次12秒预算，长度中断仅在剩余预算足够时最多再试一次。

`scene-sound.js` 为scene／agent／companion／preview提供单一语音源，sceneSpeechState返回queued／playing／ended／stopped／blocked／error；真实onstart才视为播放并降低音乐音量，8秒未启动给出受阻反馈，异常播放释放通道。180字符短句分段保留全文与Unicode，不截800字；stopSceneSpeech({source})只能停止匹配来源。onState回调和bantu:speech-state事件同步GUI；visibilitychange后台停止全部语音。`agent-speech.js` 使用消息标识及主体／会话绑定，完整页与小窗共用按钮和错误状态，朗读Markdown正文时忽略链接地址与格式符号。所有入口读取scenePreferences.voice；音色更换或试听共用既有设置。

前端入口与角色卡是非模态，普通页面不inert；打开真正的设置面板或账号保护层时，smartCompanion与原背景一同inert。bantu:sheet-changed在面板关闭后重新核对提示，不恢复旧语音。root虚拟形象使用本地SVG，新增smart-companion.css进入外壳预缓存；智能伴行开启时抑制旧自动全屏转场，原手动场景和进度动作保持可用。

### 地点现场与全局上下文 Agent：试点实现

图片或文字布局变化发出内部 scene-artwork-layout 事件，agent-dock-motion.js 在原位重新避让文字主题、重新加载按钮及提示文案；正常画面中的这些隐藏节点不作为障碍。悬浮窗仍可拖动、收起，不添加遮罩。

`public/lib/scene-artwork.js` 按主体、placeId、场景 ID／版本及 artwork URL 保存页面内图片状态，不持久化到用户计划。render.js 挂载当前 img 的 load/error，已完成图片以 naturalWidth 判断，画面未就绪时关闭隐藏热点；失败后不在每次背景重绘时自动发起同一错误图片请求。明确重试替换 img 并追加 scene_retry 参数，旧节点事件由连接状态、主体、导航版本、场景版本及尝试序号阻挡。图片回执只原位更新界面，不重建讲解、清空探索或停止音乐。文字主题使用独立 data-element 与 explore-scene-text-topic 动作，避免隐藏的备选入口抢占画中 data-hotspot 身份；用户选择文字模式后，图片迟到成功不自动切回。恢复画面把隐藏操作上的焦点移到有名称的场景画面组；离开清除 scene-text-active 布局类。横屏异常页面可滚动，正常画面继续原沉浸布局。回归：tests/frontend-scene-artwork.test.ts、scripts/verify-scene-artwork-ui.mjs 及原场景回归脚本。网络阻断和延迟为浏览器受控夹具，不代表真机弱网或音质验收。

`place-scene.js` 的手动、自动和深链接入口共用请求序号、AbortController 及 activateScene。请求回执核对主体、导航版本、发起页面、前台状态与目标 placeId；新请求撤销旧请求，同目标也不例外。loadPlaceScene 验证返回资料属于请求地点。app.js 的 hashchange 在同 scene 页切换 placeId 时也调用 navigate；render.js 动态模块加载回调先核对发起导航版本。新场景或不同 stopId 的参观重置点选、探索、提示与讲解；同一主体、stopId／手动地点、场景 ID／版本的总览或楼层往返保留探索。切换时停止旧声音、讲解请求与定位提醒；新资料未准备好时，Agent 上下文和小窗文案不能引用旧元素。关闭及前台暂停撤销元数据请求，恢复前台可重新读取被中断的目标。过期错误静默丢弃，当前手动错误交给操作入口，当前自动错误显示反馈，当前深链接错误回对应地点详情。上述行为不新增 HTTP 接口、不更改进度事实。回归见 tests/frontend-scene-loading.test.ts、scripts/verify-scene-navigation-ui.mjs 与原场景回归脚本；受控延迟、账号切换和内存计划为隔离夹具，不代表真实定位或模型验收。

sceneSourceIdentity 将地点／场景／帖子／计划历史实体加入加载上下文，sceneLoadContextIsCurrent 同时核对实体与原主体、页面和导航版本。render.js 的 syncSceneEntryNavigation 撤销已失效的手动读取，防止同 place 页换 placeDetailId 后旧结果重新开场景。store.js 的 sceneEntryPending／sceneEntryError 仅保留本页瞬时记录，不写用户库或浏览器存储；sceneEntryPendingFor／sceneEntryErrorFor 只给原身份、版本和地点返回可显示记录。place.js 在静态按钮组内切换取消／重试动作与 status／alert，取消后以防迟到的 RAF 恢复入口焦点；错误文本转义，原生网络 TypeError 转中文说明。actions.js 对已在原位显示的失败不再增加 toast，其他调用方仍收到错误。finishSceneLoad 只清理匹配 token 的等待状态，旧取消回执不会清掉新重试；后台或账号暂停清理等待状态，返回前台重新渲染地点入口。有效的手动 activeSceneLoad 阻挡自动候选。规则覆盖见 tests/frontend-scene-loading.test.ts，手机操作及同页切换见 scripts/verify-scene-manual-ui.mjs；原首页／地点布局、场景导航与自动入场脚本分别回归原契约，无新 HTTP 端点或进度写入。

自动入场的 automaticSceneEntryAllowed 在启动与回执阶段核对当前主体设置、同 stopId／placeId、前台、页面、小窗／发送／照片处理、计划编辑、面板和输入焦点；手动入口不使用这项自动策略。activeSceneLoad 保存请求与 automatic 属性，关闭自动设置只撤销自动请求，不撤销手动请求。openedVisits 只在 activateScene 成功后记入，操作忙碌或导航变化的未激活尝试可重新建立候选；重新建立时清空原定位样本，仍须新的连续停留。当前错误有反馈但不立即自动重试；用户正忙时，已失效的自动错误不打断其操作。arrivalGeneration 与 arrivalLoadController 单独绑定定位资料读取、watchPosition、定位错误及停留重采样回调；停止检测撤销读取并使旧轮次失效，旧成功不能安装第二个监听，旧错误不能关闭或清空新监听。复核：tests/frontend-scene-loading.test.ts、scripts/verify-scene-entry-ui.mjs；该脚本使用两次受控 GPS 样本及前端内存计划，不能替代实地定位验收。

现场短讲解为当前官方 API 预留 768 token 生成额度；仅完整文本被截断且还剩至少两秒时，最多重试一次至 1536 token，两次共享 12 秒时限。持续截断、供应商失败或文案串场时仍回退已核对资料。额度包含供应商可能使用的内部推理消耗，不等于页面文案长度；页面仍显示短文，已核对正文始终保留。离开候选在 Agent 对话期间最多暂存一分钟，收起对话后再显示；切页、后台、安静模式和计划站点失效时撤销。

上海自然博物馆、武康大楼、徐家汇书院、徐家汇公园、龙华寺、桂林公园与西岸美术馆七处试点已实现；当前接口、工具与仍待扩展的边界如下。产品时机与交互见[地点现场设计](产品与交互规格.md)。场景插画不可用于推断建筑、设施或实时开放事实。

- `src/services/place-scenes.ts` 是版本化试点资料；`GET /api/v1/places/:id/scene` 先用地点供应商核实 ID，再返回 AI 场景图、场景版本、候选定位圆和三个热点。上海自然博物馆与徐家汇书院场景有已收录楼层资料，武康大楼、徐家汇公园、龙华寺与桂林公园只标室外可见特征；前端入口清单 `public/lib/place-scene-catalog.js` 与服务端试点名称同步。热点有稳定 ID、锚点、可选楼层、事实摘要、依据及核对日期。七处各有一段由 `public/lib/scene-sound.js` 在浏览器本地合成的原创 BGM，无外部音频地址。`POST /api/v1/places/:id/scene/narration` 只接收 `moment`、热点 ID 与场景版本，模型失败或短期重复请求时使用整理好的资料文字。模型文案只作为补充，前端始终显示已核对的资料正文与限制，不允许短文覆盖事实。服务端对短文执行当前地点及热点的中文相邻字相关性检查，并拒绝出现其他试点地点或完整热点名称的明显串场内容；不通过时回退资料文字，该检查不等于事实核验。
- 自动进入由 `public/lib/scene-arrival.js` 和 `place-scene.js` 在应用前台判断。需由旅者主动开启；至少两次新鲜、精度不高于 50 米的定位处于同一保守候选圆并持续约 20 秒；只匹配当前计划的同一 `stopId`，编辑草稿、确认弹层、Agent 忙碌或输入焦点存在时不转场。页面隐藏停止监听。高德目录返回 GCJ02，而设备定位按 WGS84 使用；七处试点的圆心已由目录点转换为 WGS84，在线目录中的“上海市徐汇区图书馆(徐家汇书院)”归一到书院场景。浏览器测试确保高德原始坐标不能误触发。候选圆并非经过实地核实的场地多边形，只作为入口候选，绝不写入到达事实；徐家汇公园的 105 米中心候选圆不覆盖整个公园，入口识别范围尤其需要实测；真人设备与现场入口位置仍需验收。单次到访使用内存去重避免反复弹出。
- `public/lib/agent-view-context.js` 向 `POST /api/v1/agent/chat` 附加白名单页面、当前 placeId／hotspotId、可选 planId／stopId、navigationRevision 和 expectedRevision；它表达“用户正在看什么”，不是授权或已到达证明。帖子详情只附 postId，由 `resolveAgentViewContext()` 按会话主体重读可见范围、摘要与关联地点；私密帖不对其他账号开放，全文与评论须用 `community.post_detail` 读取，帖子内容不作为指令。地图页附当前选择的起终点 ID 与方式；目录地点由服务端重查，当前位置仅表示用户选择该起点，地图自选点不附坐标，方式不证明供应商可用性或路线耗时。小窗的“附带本页”可针对当前页面临时关闭；换页重新启用，关闭期间不发送页面上下文。服务端重读地点与本人计划并核实场景元素；地点目录暂时不可用时只可退到本人计划快照并标记旧资料，完全无法核实则忽略地点提示，保持对话可用。跨主体计划与无效元素拒绝；旧计划版本只标为 stale，要求模型先读最新计划。定位数据走既有临时请求，不把轨迹保存在现场上下文。
- 主动讲解采用“确定性时机选择 → 资料文本 → 模型组织短文 → 页面展示”。已实现入场欢迎和八分钟未探索提示；旅者点元素是主动请求。`scene-timing.js` 对本人当前计划中状态为 visiting 的同一 `stopId`，按计划时区计算原定结束时间，进入剩余 20 分钟至超时 30 分钟窗口后显示原计划节奏提示；入场已临近结束时该提示代替欢迎。每次到访最多三次主动提示，八分钟冷却；安静模式和页面不可见不新增提示，模型不可用回退资料文字。离开范围提醒另行由旅者开启，默认关闭；只有当前站为 visiting、现场页在前台、先在圆内稳定停留约 20 秒，随后两次新鲜且精度不高于 35 米的定位明确超出圆心半径、精度误差和额外 40 米缓冲，持续约 30 秒才提示“可能离开”。提示仅作候选，不写计划、到达或完成事实；旅者委托后 Agent 才核对最新计划和工具回执。跨刷新到访节奏及多地点并发候选尚未实现，不应宣称已完整托管参观。
- 全局小窗复用个人 Agent 的消息、工具、任务检查点和结果回执；`scene.inspect`、`scene.highlight`、`ui.navigate` 已注册为只读／界面工具。前端仅在身份和导航版本仍匹配时执行白名单高亮／跳转；从首页或地点详情发出的现场高亮会先进入已核实的同一地点现场，再点亮元素并收起小窗；有未保存计划草稿或页面目标已变化时阻止跳转。写入仍走既有服务及版本、确认与幂等校验。“已记录”“已调整”只能由工具成功回执支持。自动化已覆盖跨页现场高亮、实际私人记忆保存和小窗界面；跨对象多动作仍依赖模型逐项执行与回执，不能据此保证任意一句话都会完整执行。

地点详情 `place.js` 的 `.place-detail-actions` 统一两项主要动作；`product-design.css` 用等宽网格与 54px 高度，按最新反馈放在实拍照片分区上方，随页面滚动，不再悬浮或吸底；简约模式保留整宽按钮。`verify-home-place-layout-ui.mjs` 检查 320／390／430／1440px、主题与显示模式、三态布局、正常滚动和实际触摸入口，共 74 项；未改加入或三态业务逻辑。

参观设置以原位更新控件状态保留焦点；关闭音乐同步当前场景按钮。`scene-sound.js` 区分现场朗读与音色试听，普通背景重绘不打断试听，`ui.js` 在设置面板关闭或替换时停止试听。`agent-dock.js` 与完整对话共用账号隔离的文字草稿，主体切换不捕获旧账号 DOM，也不将旧文字填入新账号；存储不可用时仍允许当前会话隐藏／恢复小窗。`verify-companion-controls-ui.mjs` 使用隔离身份与语音适配器复现并回归这些行为，不将适配器测试当作真机音质验收。

`public/lib/chat-composer.js` 通过 writingDraft 保存当前主体的 chat-composer/personal 文字及待填入问题；输入节点携带 data-chat-owner，重绘、切页、输入及 pagehide 捕获本主体文字。beginChatComposerSubmission 捕获原主体和精确文本，仅清除匹配本次提交的输入；失败恢复到原主体草稿，当前新文字优先。commands.js 在成功、异常及 finally 中检查请求主体，旧请求不能写入新账号聊天状态或解除其 pending。小窗取消独立 savedDraft 缓存；textarea 自动增高，问题选择位于可滚动 chatList，grid-auto-rows:max-content 防止折叠选择器被压成 2px。照片仍走现有内存与上传流程，不进入文字草稿。回归见 tests/chat-composer.test.ts、tests/frontend-chat-retry.test.ts 与 scripts/verify-chat-composer-ui.mjs；刷新后未确认请求的恢复仍走既有任务检查点，不能把文本暂存宣称为跨刷新幂等重试队列。

现场“请伴途帮我”带当前计划上下文进入真实工具循环。若用户要求核对当前日计划而模型只给口头建议，服务端先追促读取 `plans.list`；仍无成功读取回执时明确表示尚未核对，不宣称已经判断或修改。小窗预填内容立即显示，历史消息慢加载时保留旅者已修改的输入。
- 音频控制与正文独立：本地原创/授权 BGM，播放状态由旅者设置；有声讲解时压低音乐，退出现场和切换主体立即停止。语音失败退回文字，字幕与减少动态效果不依赖模型或音频服务。场景素材按已有本地素材管理与来源核对流程入库。

`tests/place-scene.test.ts` 覆盖七处场景的资料边界、定位漂移／新鲜度、跨日计划时间判断、归属／热点／版本、帖子私密权限与全文工具读取、地图端点核实、模型实际工具写入、目录故障降级与接口；`scripts/verify-place-scene-ui.mjs` 用隔离数据和浏览器覆盖手动／模拟自动进入、七处各三个热点、武康大楼室外场景、徐家汇书院 1F 图往返、已核对正文与模型补充同时显示、音乐开关、模型收到已核实上下文、真实私人记忆与探索资料整理、小窗高亮、本页上下文的真实请求开关、安静模式抑制计划提醒、计划提醒委托入口和 320px／390px 页面无横向溢出。真实设备现场定位、浏览器朗读、长时间安静模式和弱网仍需真人验收；截图和模拟定位不能替代现场可用性结论。

移动端现场以横屏沉浸画面为主要体验。七处 AI 生成 JPEG 为 1774×887、2:1，素材为 `public/images/places/scene/*-v*.jpg`；生成工具、提示词及实拍参考清单保存在 `public/images/places/scene/generation-prompts.json`。`place-scenes.ts` 既有六处场景版本为 2，西岸美术馆新增场景版本为 1，热点增加可选 `story` 短讲解，原资料正文与依据保留。`scene-hit-regions.js` 按新画作手工校准百分比多边形，画面与点击区域不裁切、不独立运动；`scene-hit-interaction.js` 保留真实触点命中及拖动／取消保护。小屏中的细小画面区域不强行扩到与画作不符的尺寸，详情面板提供同主题的 44px 文本按钮替代。

`scene.js` 在手机横屏固定完整画作，仅显示44px返回按钮；隐藏音乐、设置、全屏、Agent入口和讲解工具栏，正文仍以非模态浮层显示并可拖动、滚动。点击画面空白处通过scene-hit-interaction.js收起文字，继续点击图中元素仍触发讲解与音乐。竖屏保留完整操作，图片失败的恢复与文字入口不受影响。`scene-presentation.js` 负责详细资料、关闭短讲解和由用户点击触发的全屏／横向请求；以稳定的 document 根元素进入全屏，选点重绘不会退出，离场及普通导航释放本应用取得的全屏。浏览器不支持方向锁时自然旋转仍可使用。`agent-dock-position.js` 选择就近可用位置避让浮层；`agent-dock-motion.js` 按实际固定导航计算边界，矮屏简化标题区并保留完整对话入口。`ui.js` 对模态面板同时隔离页面、底栏和小窗，关闭恢复原 inert 状态。

参观偏好仍由 `scene-preferences.js` 按身份共用，`scene-settings.js` 提供跨地点面板；原定位守卫、进度与工具权限不变。点选立即播放 `story` 与原创合成 BGM，模型补充仍通过原接口获取并放在详情中；重听优先同一短讲解。关闭文字只取消现场朗读，音乐维持所选状态。环境微粒与光影不移动点击区域，安静及减少动态效果停用。浏览器朗读使用设备已有中文音色，未新增云端 TTS。

横屏异步请求以代次、导航版本、主体和前台状态校验；离场、原生退出或后台切换使旧请求失效。迟到的方向锁在没有新场景取得全屏时再次解锁，不干扰新会话。后台切换停止包括设置试听在内的全部语音及音乐；前台恢复只同步控件，不自动播放。普通重绘仍保留正在进行的音色试听。自动音色排序先区分普通话与其他中文语言，再比较自然音色；用户显式选择始终优先。

`scene-sound.js` 保留用户手势内创建及 resume 音频上下文，初始化同步失败不缓存失效 Promise；启动结果区分 true（播放）、false（设备失败）与 null（取消／被替代），旧上下文的迟到完成不能关闭新上下文。`sceneSoundStarting()` 驱动可取消的启动状态。`place-scene.js` 按请求代次、导航、主体、地点及前台状态过滤音乐回执；讲解采用代次与 AbortController，替换旧请求并在返回后再次校验，保留资料正文。`suspendPlaceScene()` 撤销讲解、定时提醒、定位监听及横屏请求，停止场景和试听声音；回到前台只重新启用合条件的监听及提示计时，不自动播放。账号暂停／恢复事件由 app.js 接入同一生命周期，account-context.js 同时隔离 agentDock；ui.js 的弹层关闭通过 `restoreBackgroundInert()` 维护独立账号锁及最终恢复状态。`verify-scene-session-ui.mjs` 在隔离内存账号、实际 Cookie 切换与 Edge 触摸界面中验证这些竞态；延迟音频、讲解及可见性适配器不证明真机音质、模型生成质量或现场定位。

`scene-story-motion.js` 在中央重绘后挂载讲解窗口移动，使用标题区 pointer capture、6px 阈值、取消及方向键事件；复用视口限位计算，按身份与场景会话在内存最多保留 12 组几何位置。竖屏保留窗口原占位；旋转／visualViewport 变化重新测量响应式宽高，不独立移动底图或热点。移动通知 `agent-dock-motion.js` 重新避让。普通重绘沿用原位置；既有按压延迟机制保留拖动期间的 DOM。聊天小窗采用独立上下文行与统一 44px 输入／工具栏，调用 `renderAgent({compact:true})` 仅改变短建议和输入提示；对话发送、草稿及工具链仍共用原实现。`components.js` 为全部前往／游览标题使用同一 heading 结构，阶段及地点名称共同使用 `--phase-heading-height`，含调整按钮时为 44px。


Agent 导航继续进入完整页面；`agent-dock.js` 绘制独立非模态小窗，`agent-dock-motion.js` 处理拖动阈值、键盘移动、位置保存、视口变化和避免底栏／地点操作栏，`agent-dock-position.js` 校验与限制坐标。悬浮入口与小窗均可移动，收起与关闭不同，关闭后从“我的”恢复。没有 scrim、背景 inert 或页面滚动锁；输入草稿按主体隔离，在收起、隐藏、换页与完整对话交接时保留。真人 Android／iOS 软键盘、设备音色和现场 GPS 仍需实测。

### 往日记录与记忆

读取与维护触发过期处理；旧进行中不清理。普通过期日先处理适用记忆及未执行方案，再把原日期对象移入独立的往日记录集合，保留原安排、完整事件和已有内容快照。当前列表与随行只访问活动集合，历史补记和纠正只修改原记录，不启动导航、不迁移节点、不顺延今天或其他历史地点。

plan-library 的持久化仍为 JSON 数组，历史条目以 historyArchivedAt 区分，恢复时分离活动和历史集合。历史访问校验主体，写入强制校验 expectedRevision 和原计划时区下的 30 天窗口；之后只读，仍可明确删除。修改历史时将关联旅行记忆标记 staleAt，保留原文与原摘要快照。已有历史版本仍按最多 5 份内容快照的规则保留，不宣称恢复此前已删数据。

## 执行与版本契约

三态详细规则以[计划与进度三态转换逻辑](计划与进度三态转换逻辑.md)为准：同一账号所有日期最多一个进行中；planned 可出发、直接报告到达/完成、跳过；en_route 可到达、中止、跳过；visiting 只能完成，纠错另走明确修订。超过时间不会自动产生事实。

实际发生时间与计划时段分开，缺少实际到达不生成游览时长。进行中跨日记录保留，普通过期计划归档未执行内容后将原日期对象转入往日记录，保留至主动删除。原事件与已有内容快照可查看；此前已删数据不能恢复。删除日计划或往日记录会移除该执行对象，不能沿用静态方案的“不影响进度”承诺。

历史补记、纠正以原计划时区的当地日期计算窗口：计划日过去 1–30 天（含第 30 天）可修改，第 31 天起只读；详情返回截止日期。补记限完成或跳过，可将到达和完成一次性原子提交，时间须有效、非未来且符合原日期/跨日规则。纠正限未完成、已完成、已跳过，保留原事件及修订关系；历史不能改为前往中或游览中。修改只影响该记录，不导航、不迁移节点、不顺延今天或其他历史地点；关联记忆保留原文并标记来源变动。个人记忆仍允许编辑文字，保留旧路线快照和 staleAt，不能通过改文字将旧摘要视为当前事实。

执行与恢复等操作提交 expectedRevision；内容变更后旧请求冲突，前端须重新读取。载入涉及已有计划或进度时先返回冲突及确认信息；确认期间状态变化必须重新核验。结果页使用服务返回视图，不能拿旧存储状态覆盖当前事实。

计划 PUT 编辑也支持 expectedRevision（非负整数）；当前界面提交打开预览/编辑器时捕获的版本，服务端在实际更新前校验，过期返回 409 REVISION_CONFLICT，非法值返回 400。输入不会因冲突自动清空。为兼容内部及旧客户端，省略字段仍沿用原编辑行为；不能据此宣称所有外部调用已强制乐观锁。

地点跨日加入在既有 POST/PUT /plans 请求中携带可选 `expectedCarryTargets`：每项包含 `localDate`、`planId` 和 `expectedRevision`；目标日尚无计划时后两项为 null，已有计划时使用 ID 与非负版本，旧记录缺版本按 0 处理。服务端在同步保存/更新入口核对目标日的归属、唯一对象及版本，变化返回 409 REVISION_CONFLICT，非法确认资料返回 400；核对失败不改源日或目标日。前端确认前也重新读取目标版本，减少过期写入。字段省略时保留已有 T7 迁移兼容路径，不增加接口或执行事件。

个人记忆 PATCH 支持 expectedEntryVersion（正安全整数）。当前编辑界面始终提交捕获的条目版本；服务在任何内容变更前核对，过期返回 409 ENTRY_VERSION_CONFLICT，非法类型或值返回 400 INVALID_INPUT，失败不修改原记录。重新打开旧草稿时读取最新原文，仅在用户明确核对后改用这次读取的版本，仍须通过提交时校验。未提供版本的内部/旧客户端保持兼容行为，不能宣称所有外部写入已强制版本保护。

## HTTP 约定

下表路径省略 /api/v1。成功使用 data 信封，列表可带 meta.nextCursor；错误含 code/message。是否有路由只证明入口存在，401/业务拒绝不等于该功能成功验收。字段与状态的精确约束以对应路由和服务类型为准。

统一前端请求携带 `x-bantu-principal`，值为页面当前主体；服务端仍用 Cookie 验证真实身份。二者不一致时，在路由读取业务资料或修改数据前返回 `409 SESSION_CHANGED`；标识非法返回 400，缺失有效会话仍为 401，客户端标识不能授权。`POST /session/guest` 是会话恢复入口，不做此比对；未携带标识的兼容客户端沿用原 Cookie 鉴权，不保证旧页面主体一致性。

account-context.js 在跨页账号变更信号、重新聚焦或页面可见时读取实际会话资料，只核对，不将另一账号资料写入原页面状态。新核对撤销并替代旧核对，各回执绑定当前核对、原页面主体与accountContextEpoch；旧/me不能遮蔽新Cookie核对或解除保护。发现切换后暂停统一请求、锁住原页面及编辑面板，保留输入和原焦点。暂停／恢复递增序号，api.js和会话恢复捕获principalId、kind与该序号，同账号暂停后重新核对也不接纳此前的业务回执；普通同主体资料刷新不因对象实例改变而废弃合法回执。切回原账号可恢复；明确刷新后才使用当前账号。核对网络失败不擅自恢复已暂停页，也不把断网冒充账号切换；已实际提交的业务不伪装回滚，应读取真实结果，不能重放写入。回归见 `tests/account-context.test.ts`、`tests/frontend-account-context.test.ts`、`tests/frontend-agent-task-lifecycle.test.ts` 及 `scripts/verify-agent-account-isolation-ui.mjs`。

白天改期由 src/services/plan-daytime.ts 生成内容预览，PlanLibraryService.previewDaytime 绑定当前主体、源版本与所有查找日期（含未占用、跳过的满额日期及前一日跨午夜占位）。previewKey 摘要包含日期、独立到访窗口、保留项、路线和费用；applyDaytime 不接受客户端提交的站点快照，按当前状态同步重算并比较摘要，变化返回 409 REVISION_CONFLICT。成功只在隔离副本完成 update 及所有目的日期校验后替换在线计划库，HTTP 持久化仍走统一状态存储；不生成执行事件。私有计划及不合法日期／版本请求按原鉴权与 400 校验处理。

迁入多个日期时 migrateNextDayStops 先构造并验证全部目标副本，再一次提交；固定或有执行事实的既有时段不能自动顺延。新建跨日计划同样在目标校验后才加入源计划，避免失败残留。路线费用按 stopId 或 routeLegRef 归入真实目标日；旧起点、跨日、时效及 demo 路线不能成为未来有效道路估计，已支付或未核对的失效关联费用拒绝自动删除。日计划归属语义沿用 T7；白天调整须用户确认。public/lib/plan-daytime.js 保护原面板节点、主体及 navigationRevision；旧预览不重开面板，已保存回执不因后续读列表失败而冒充保存失败。回归见 tests/plan-daytime.test.ts、tests/plan-daytime-http.test.ts 与 scripts/verify-plan-daytime-ui.mjs。

## 当前主要接口

旅行成就由 `plan-library.completedVisits(actorId)` 投射活动计划与归档记录中的有效 completed 站次，再经 `travel-achievements.ts` 分组计算卡片、等级与徽章。以 planId + stopId 去重，按 placeId 汇总，排除静态方案与其他主体；执行纠正按原有 replay 规则处理。兼容已保留的旧完成事实，缺失时刻返回 null。成就不另存可篡改的累加计数，不新增写入奖励接口。删除执行对象后的统计依据剩余事实变化。

`GET /achievements` 返回 summary（placeCount、visitCount、revisitCount、shiningCount）、cards（placeId、name、cityCode、count、tier、nextTier、progress、firstVisit、latestVisit、visits）、tiers 与 milestones。visits 保留 planId、stopId、localDate、timezone、completedAt、archived 和来源名称；只返回 Cookie 主体自己的记录，沿用 x-bantu-principal 一致性保护。前端 loader 校验主体与请求序号，身份切换清除缓存；API 失败显示重试，不伪造奖励。Agent achievements 页的统计由服务器重新读取并核验，浏览器仅提示选中地点。

随行接口详见[伴途随行整体规划](产品与交互规格.md)。context/advice 的定位字段为 position={lat,lng,accuracyMeters,measuredAt}，设备位置须两分钟内且误差大于 0、不超过 200 米；context 只返回短期道路/天气视图。无有效定位、演示/失败路线保持 eta=null，不按直线或固定分钟补值。执行出发时可显式传 skipRouteEstimate=true，记录用户报告的事实但不估算路线。

advice 传 expectedRevision、change=rest/rain/time/replace、transportMode，以及休息 minutes 或当日 deadlineMinutes。候选最多 3 份，返回 previewId、有效期、绑定参数、逐站变化、道路与结束时间影响及未知费用。无必要坐标、开放资料或可用道路时返回准确无结果。预约、必留、锁时、执行历史及已付款/付款状态未知费用受保护。

当前首页使用 companionRequest.action=delegate，起始请求包含 planId、expectedRevision、stopId、change、transportMode，补充回答使用 sourceMessageId；cancel_delegate 取消待补充任务。personal-agent-delegation.ts 检查身份、版本与当前站点，runPersonalAgent 获得绑定任务范围。助手消息的 companionDelegation 包含状态（needs_input/applied/unchanged/unavailable/cancelled）、任务目标及成功回执中的 outcome；commands.js 和 loaders.js 在实时回复与刷新中保留此字段。模型工具包括 context、ask、keep、preview、apply；查询工具可用，普通写入工具在工具列表和实际调度中同时移除。自动应用只接受本任务成功 preview 回执中的凭据及参数，一次任务最多一次应用；缓存与请求重试不再次顺延。

旧 Agent 消息可附 companionRequest：start 包含 planId、expectedRevision、stopId、change 和 transportMode；preview 使用 sourceMessageId 及 minutes/deadlineMinutes；apply 使用 sourceMessageId、previewId；cancel 使用 sourceMessageId。后续请求只读取当前身份拥有的原助手消息，不接受客户端补写快照或伪造候选参数。assistantMessage.companionAdjustment 保存目标、阶段、候选及原因，聊天刷新可恢复；采用仍需原建议在服务端有效、计划版本/事实匹配。clientMessageId 的幂等摘要包含 companionRequest，原文相同但目标不同不能复用同一消息标识。

apply 传 previewId、expectedRevision、params 和 actionKey；凭据绑定主体、日期计划、内容/事实摘要与用户参数。preview 的 placeId 指定模型查询后选定的替代地点，targetStopId 指定具体待进行到访；目标必须在同一绑定计划内且未受保护，地点须目录有效、同城及附近范围内。雨天保留未受影响室内站的原时段，不仅替换列表首站；替换时优先保留原时刻，实际道路来不及才顺延。预览有限有效期，事实、日期或版本变化后重新预览。同步保存新计划版本与 companionReceipts，重复确认先返回原回执；回执随原计划持久化，最多保留 64 个，普通列表不暴露。源方案与已发生执行事件不被临时建议修改。

## 社区与收录接口补充

- `CommunityService` 保存发现、评价、帖子、举报和申请状态，与旅行、会话一同写入本地 SQLite。
- 展示昵称：登录账号在「我的」页维护社区昵称（`PATCH /api/v1/me`，注册时默认与账号名一致）。发帖、评论、回复、地点分享与评价表单均不提供昵称输入，也不读取旧游客昵称缓存；提交自动使用账号资料。游客可阅读公开内容，发表评论等写入时进入账号入口。

- `GET/POST /api/v1/community/places`：公共列表只返回审核通过地点；支持搜索／标签／城市／排序（`newest|rating|reviews`）与发布。
- `GET/DELETE /api/v1/community/places/:id`：审核通过地点公开可读，未审核/被退回地点仅作者可读；作者可撤回。
- `POST .../:id/reviews`：审核通过后才能新增或更新自己的评分与评价。
- `POST .../:id/submit`：作者提交核实资料。
- `POST .../:id/decision`：审核决定，需要独立审核员凭证。新版页面提交 `expectedSubmissionVersion`；资料重提或状态已决定时返回 `409 REVISION_CONFLICT`，不收录新资料、不重复写处理记录。缺省版本的旧客户端仍按原契约校验待审状态，不保证抵御资料重提后的旧决定。
- `POST .../:id/reports`：举报内容并说明理由；同一身份重复举报更新理由，不能举报自己发布的内容。
- `GET/POST /api/v1/community/posts`：公共列表仅返回公开帖子；发布可设置 `visibility: public | private`，省略时保持公开以兼容旧客户端。帖子可关联最多 12 个地点（`placeRefs`），也可附带最多 4 张压缩照片。旧版单地点字段 `placeRef` 仍可读取。
- 公开帖子搜索匹配完整公开集合的正文或昵称，`GET /api/v1/community/posts?stable=1&query=...` 返回稳定分页。关键词最多 10000 字，去两侧空白并统一小写；游标绑定相同规范化关键词，条件变化返回 400。长关键词/游标改用 `POST /api/v1/community/posts/search`，JSON 为 `{query, cursor?}`，`limit` 仍为 URL 参数；公开查询始终排除私密帖，作者从自己的发布列表查询私密内容。
- 游客可使用帖子与方案分享的两条只读 POST 搜索，长关键词、游标和方案码不因采用请求正文而被当作写入；其他社区写入仍须账号。社区地点的备注与标签接口先检查地点是否可访问，等待请求正文后提交前再次核对撤回／权限，个人内容仍按主体隔离。回归见 `tests/community-guest-search.test.ts` 与 `tests/community-hidden-place-note.test.ts`。
- `public/lib/post-feed.js` 统一查询、加载更多及重读范围：返回社区时重新读取至原最旧记录的时间/ID 边界，不能只读取第一页或保留已撤回/私密卡片。响应检查主体、查询、请求序号及分页引用；失败保留条件与重试，不冒充空结果。按原帖子屏幕位置恢复，用户滚动或改变页面、筛选后停止追随；关联地点返回及照片大图沿用已有返回路径。
- `public/lib/render-interaction.js` 在鼠标/触控按压期间延后全页重绘，使原控件保持连接至原生 click/submit 分发完成；多次重绘合并为最新状态，所有触点松开、取消或窗口失焦后恢复。键盘操作不进入按压等待。`tests/frontend-post-feed.test.ts`、`tests/frontend-render-interaction.test.ts` 及 `scripts/verify-community-reading-ui.mjs` 覆盖读取边界、隐私复核、异步查询与真实按下/请求完成/松开的时序。
- `PATCH /api/v1/community/posts/:id`：作者修改可见范围。设为 `private` 后，正文、图片、评论及旧链接仅作者能访问，不进入公开列表、分页和社区搜索；其他人的旧收藏快照会移除。再次公开不会恢复已经移除的他人收藏。
- 发布表单提供“谁可以看”：公开或仅自己可见，选择随草稿恢复。私密发布后进入“我的发布”；作者在帖子详情点击“可见范围”修改设置。私密卡片和详情明确标注“仅自己可见”。历史帖子没有此字段时保持原公开状态；恢复时未知状态按私密处理。
- `GET /api/v1/community/posts/:id/images/:imageId`：读取帖子照片；帖子 JSON 只返回照片 ID、格式和说明，照片数据通过本机应用接口按需读取。
- `POST .../posts/:id/like`：点赞切换（同一身份重复点赞等价于取消）。
- `POST/DELETE .../posts/:id/comments[/:commentId]`：发表评论或回复某条评论（通过 `parentCommentId`）；评论按楼层展示，回复保留在对应楼内；只能删除自己的评论，已有回复的评论会保留删除占位以维护上下文。
- 评论编辑由 public/lib/comment-drafts.js 按主体及帖子/回复键复用 writingDraft 暂存文字和展开状态；app.js 在输入与展开时立即保存，render.js 在重绘时恢复当前编辑焦点与选区。成功回执只清除相同的已提交文字，更新后的草稿不清空，账号变化后不应用旧回执。失败在当前表单显示中文重试说明。回归见 tests/frontend-comment-drafts.test.ts。
- public/lib/post-interaction.js 维护主体＋帖子级互动槽：点赞、评论、删评论共享 engagement 槽以顺序应用完整帖子回执，收藏使用独立 favorite 槽。community.js 在读取评论文字后开始等待，finally 释放对应令牌；不同帖子互不阻塞。views/community.js 与 views/favorites.js 读取同一等待状态，重绘保留 disabled／aria-busy、短文字及朗读状态。API 继续核对主体，旧主体不能应用回执；收藏成功提示还核对导航版本。慢请求及实际手机触摸回归见 scripts/verify-post-interaction-ui.mjs。
- `GET /api/v1/community/mine`：当前身份发布的帖子（含私密帖）与地点（含审核状态）。Agent 的“我的发布”查询也只返回当前账号的私密帖子，其他账号及游客不能获取私密正文、照片或快照。
- `GET/POST /api/v1/community/plan-shares`：方案分享列表（支持关键词搜索）与发布；发布时自动解析方案各站所在城市。
- 界面先展示公开预览，再点击“公开发布”；取消或 Esc 不请求发布。预览按实际方案码展示名称、城市、每天地点、时间和地图位置，保留空白天；不附出行日期、费用、私人笔记或实际进度。发布前再次核对原账号与方案内容，变动要求重新预览；重复点击不重复提交。
- `POST /api/v1/community/plan-shares/search`：按关键词搜索方案分享。
- `DELETE /api/v1/community/samples`：清除全部样例内容；仅平台审核员凭证可调用。清除后即使重启也不再自动注入。
- `GET /api/v1/community/moderation`：审核台队列（待审核、被举报、审核记录），需要审核员凭证；待审包含坐标、来源坐标系、核实依据及 `submissionVersion`，不返回申请人内部主体 ID。每次提交递增申请版本，版本随持久化保存。
- 收录地点合并到 PlaceProvider，供目录、详情、收藏、计划、地图和 Agent 的地点搜索共同使用；未提供的开放时间、费用、设施和建议时长保持未知。
- `BANTU_SEED_DEMO` 开启时自动注入样例社区内容（作者均为「伴途样例」，地点带（样例）后缀），覆盖全部四种审核状态；仅当库内没有样例且未被清除过时注入，重启不重复。

## Agent 入口与工具授权

### 当前入口与业务责任

个人对话经 /api/v1/agent/chat，调用 src/services/personal-agent-runtime.ts；不需要创建 Trip。页面与 Agent 调用同一计划、收藏、记忆和社区服务，服务端注入身份并检查归属、版本与参数。

首页四类临时变化由 personal-agent-delegation.ts 接入 personal-agent-runtime.ts 的真实模型循环，模型读取上下文、选择参数或地点并调用核验/应用工具；工具成功回执驱动页面刷新与变更展示。未配置模型时明确不可托管，不走规则替代。原 personal-agent-companion.ts 仅兼容旧消息的手动预览和确认，不再承接首页默认入口。必要追问会暂停后续工具，回答建立新的绑定模型任务；断线可通过任务检查点继续，已保存操作不重复写入。

个人任务保留应用侧 1M 上下文预算，以 UTF-8 字节作保守估算并预留工具与输出空间；该数值不改变供应商原生上下文窗口。默认单轮输出8192，长度截断可一次提高至16384；非法或截断工具参数整批不执行，不修补或猜测参数。单次处理最多64次模型调用、192个工具步骤，续办累积上限256次／768步；成功写入回执与任务检查点绑定，继续不重放已保存操作。连接探针仍为15秒，普通请求默认30秒，个人运行时传入的本轮60秒期限优先于供应商实例默认值。超时涵盖fetch和响应体解析，即使底层忽略AbortSignal也会结束等待。停止任务通知当前模型轮的AbortController；已经进入的业务写入仍完成或失败后返回实际回执，不假装回滚。

personal-agent-tool-discovery.ts 在完整授权工具集合内按当前指令提供常用工具，并通过 tools.discover 读取其他领域说明、在下一轮启用完整参数定义；发现不执行操作，不扩大实际调度权限。创建、复合指令和首页托管保留各自范围，笔记、帖子、交通或私人资料等复合动作不能因创建目标而被丢弃。personal-agent-plan-context.ts 仅对明确查询／调整／创建／休息任务预读本人最新计划，带ID、版本、时段和完整性标记；普通闲聊不自动读取私人计划。超过30份或24KB的快照不代表完整库，仍可调用 plans.list。写入始终再次验证版本，预读不是保存成功证明。

personal-agent-planning-goal.ts 的 planningGoalsFromText 分别提取每份创建目标，planningGoalFromText 保留首目标兼容入口。多份目标由 plans.create 的 creationIndex 绑定各自天数与每日地点数，保存前逐项校验；后续收藏、比较、编辑或删除旧方案不取消创建要求，也不串用另一目标的数量。“不创建新方案／不再创建／不新建”是禁止创建，不能从这些分句恢复创建目标；直接调整原日计划完成后无需新的创建回执，调度层也阻止模型擅自调用 plans.create。否定限定在相邻动作，“时间不足”不取消另行明确的创建要求。引号及明确原文中的行程文字仅作为资料。完成判断核对实际独立对象回执及目标形状；旧检查点中保存的短方案不冒充完整目标，确认／继续保留已成功操作，不重复创建。

personal-agent-authored-text.ts 支持只有合法单行title的笔记，title与text不能同时为空。agentAuthoredOriginals 为每份明确整篇原文分配跨笔记／帖子的 sourceIndex；存在同类多篇时工具必须提供该序号，组合后的标题和正文仅统一换行与外侧空白，所属类型和原文须在写入前匹配。引号内容、中文“原文是／内容如下”和英文 exact text／original text 不授予其他动作。原文本身的重复保留，用户要求两份相同原文仍以独立索引和实际对象分别保存。已成功索引不得重复使用；发帖预览不能计作发布。pendingAgentAuthoredOriginals 结合 task.writes 中真实完成回执核对未完成篇目，最多两轮收尾纠正后仍缺项则保留 interrupted 检查点并准确说明，不能只按模型声明结束任务。原生上下文超限或累计硬上限则终止检查点；未完成原文及当前对象冲突只能补充说明，不能把已终止任务改回 interrupted。确认续办从原task.requestText读取授权与原文，不以“确认删除”等短答替代原任务。

纯“继续／继续处理／继续刚才的任务”只续办同一会话的 interrupted 任务。最新任务已完成、已停止或因上下文／累计上限终止且没有待确认操作时，直接返回当前状态与可用结果入口，不调用模型、不新建任务或重复写入；终止原因随检查点保存，重建服务后仍生效。completed 表示本轮检查点结束，终止说明仍须准确列出未完成事项。明确提出新需求或“再保存一份”允许新任务；其他会话独立处理，超时仍保留可继续的检查点。回归见 `tests/personal-agent-terminal-checkpoint.test.ts`，实际手机尺寸HTTP与触摸验收见 `scripts/verify-agent-terminal-task-ui.mjs`。

原文序号属于另一类型或不存在时，错误回执单独列出本类型可用序号，要求仅修正 sourceIndex、保留标题正文；不再误报为文字不一致。合法序号仍严格检查原文，多篇同类型仍必须提供序号。回归见 `tests/personal-agent-authoring-repair.test.ts`。

`personal-agent-write-state.ts` 将历史写入事实与当前完成状态分开：历史成功回执用于防重复，结束或续办还读取当前主体的真实笔记、帖子与方案。对象已删除、原文被修改、方案不再满足指定天数／地点数时，保留检查点并明确冲突，不自动复活或覆盖。用户在同任务明确要求的后续成功修改／删除按最新实际动作核对；动作顺序不能由幂等键首次插入顺序推断。帖子可见范围经过反向修改后，再请求相同目标须重新准备预览并等待确认；仅当前状态已匹配才重放原成功结果。回归见 `tests/personal-agent-recovery-current-state.test.ts`。

当前对象冲突还必须在工具调度及确认提交前执行写入守卫，不能只发系统提示后让模型用新版本覆盖。继续旧任务不能修改／删除冲突对象，也不能换参数另建自由笔记／帖子替代；读取及另一明确尚未完成的独立原文仍可执行。待删除对象在等待确认时被修改，旧预览失效并保留续办，不提交删除。明确创建后修改／删除的正常流程按真实成功动作核对，规划工具过滤保留复合请求中明确授权的修改。

personal-agent-write-intent.ts 在业务工具调度前及待确认快捷提交前执行明确只读／禁写约束，覆盖支持的中文／英文创建、修改、删除等指令；不是只靠系统提示让模型自觉遵守。笔记、计划、昵称及帖子相关限制按工具操作区分，分句只读仍允许另一个明确授权的领域动作，无范围的禁止写入仍约束全部写入。原文和正确配对的引号属于数据，英文单词内don't等撇号不作为引号起止。失效确认通过 invalidatePreparedWrite 记录失败、清除旧预览并保留原任务、已成功回执与续办检查点；继续时须重新准备有效预览，不能用失效令牌提交。

personal-agent-runtime.ts 在待确认边界先处理明确取消／针对原操作的否定，“取消，不要保存”等语句直接清除待办，不启动新的模型写入流程。取消并另有解释／其他委托时，保留原预览为资料后建立新任务，旧预览不提交；原文中引用“取消”不撤销待办。确认提交前重新检查原task.requestText限制，恢复的旧检查点也不能绕过权限；确认的异步地点读取完成前任务被取消时，不再发布。已完成改动保留，不承诺撤销已提交操作。回归见 `tests/personal-agent-pending-cancel.test.ts` 与 `tests/personal-agent-write-intent.test.ts`。

personal-agent-post-visibility.ts 为 Agent 发布和可见范围修改提供独立参数与预览。明确私密请求即使模型漏传visibility也不会默认公开；标题／正文中引用“private／私密／不要公开”不自动变更范围。本人修改使用expectedVisibility核对旧范围并等待“确认修改”，公开发布或私密发布沿用发布确认；旧待确认记录缺少范围时拒绝直接发布，要求重新预览。成功回执通过personal-agent-result-links.ts提供作者可访问的帖子入口，不扩大他人的访问权限。

personal-agent-model-failure.ts 只提供固定安全错误说明。供应商原生上下文超限结束本次无法继续的检查点并提示新对话或更换模型，不能无限续办相同超限输入；已保存操作保留。超时、取消、非法参数、空回复及拒绝分别说明实际状态，不泄露供应商错误原文或把未完成任务写成成功。

浏览器发送个人Agent指令使用已有的新鲜定位，不先阻塞等待GPS；真实出发和明确更新路线保持自己的定位流程。public/lib/commands.js 按身份、会话与clientMessageId绑定本次回执，模型回复先显示并解锁输入，再同步实际受影响页面。慢刷新、旧会话轮询和旧请求finally不能清空新任务或覆盖其状态。agent-task-status.js 在本地POST等待中只更新真实步骤／停止状态，不读写历史、不替代POST回执；恢复的后台任务另走历史同步。agent-view-sync.js 按主体合并并发读取、等待共享完成，失败资源保留为只读重试，不重放写命令。

日期回执还核对原查看日期、navigationRevision与planDateSelectionRevision。有效日期选择每次递增序号，先切开再切回也会废弃旧跳转意图；已保存业务结果仍显示。恢复的远端任务首次被观察时记录日期和导航，完成时同样核对。会话选择由agent-conversation-selection.js提供独立序号，新建／切换／回退／删除、主体恢复和404回退均使旧读取失效；旧idle状态回执还核对最新消息回执，不能在新消息已完成、pending又回空值时装回旧任务。会话删除／改名后的列表刷新与原面板内容身份绑定，编辑器关闭后，迟到删除成功或列表回执均不能关闭／覆盖后来打开的设置面板。

public/lib/http-request.js 给普通API提供30秒、聊天执行5分钟的有限等待，并保留调用方更短的取消／期限。成功响应必须可解析且包含data，Agent回执必须有非空回复；异常体不能生成“已收到”式成功。会话恢复单独限制15秒，运行时和独立存储标记共同限制8秒内一次，不能因刷新通知覆盖重试时间戳；reload返回后也结束原请求。账号核对限15秒，失败保留账号暂停状态，可再次核对。

personal-agent-places.ts 按任务复用 places.search / places.nearby 返回的真实地点 ID、坐标及基础资料，用于创建节点、路线估时与 plans.route，避免同一方案逐次请求全部地点详情而使查询故障阻断保存。显式 places.detail 仍读取最新完整资料；未查询到的 ID 必须走真实目录核验。续办只恢复当前任务五分钟内的成功搜索回执，不跨任务或账号共享私人地点标签。routes.estimate 的供应商错误作为失败步骤返回；它只查询，地图中的路线必须由 plans.route 保存。普通规划在道路未知时可保存地点安排并说明待估，首页自动托管仍必须取得可核验道路才能应用，不放宽其保护条件。

明确创建方案时，运行时优先提供本任务所需地点、计划和保存后路线工具，同时保留复合指令中其他已授权领域；模型不得把查询结果或自然语言回答当成已创建方案。plans.create 在写入前核对用户明确指定的天数、每天地点数和地点所属城市；成功回执是“已保存”的唯一依据。地点搜索按用户明确指定的受支持城市/上海区县限定范围，未指定时沿用默认范围。先保存完整地点安排，再调用 plans.route 补道路；同一失败路段不重复请求，供应商限流时停止后续路线调用并明确报告“地点安排已保存、交通时间待核对”。多动作委托保留完成其他已授权动作的机会。用户继续任务时读取已有成功回执，不重复创建同一方案。

plans.create 的每个 stops 项可传 transportMode（walking／transit／driving），保存为 preferredTransportMode，包括无当前位置的首站。plans.route 的 mode 可省略，此时按目标节点 preferredTransportMode、原匹配路线、walking 依次选用；显式 mode 改所有本次更新的入站路段及其目的地选择，首站原选择保留。plans.route_segment 仍必须提供 mode、只更新指定目的地；成功后同步 preferredTransportMode 并清除旧 estimatedTravelMinutes／estimatedTransportMode。道路失败及查询中版本变化保持原存储与付款保护。新增 tests/agent-stop-transport.test.ts 覆盖创建、逐站道路及单站一致性；verify-agent-plan-creation.mjs 使用实际官方模型和在线供应商，verify-agent-stop-transport-ui.mjs 从该真实结果生成的临时快照验证手机显示，页面回放没有再次查询真实道路。

普通对话的 progress.record 出发共用 plan-departure.ts 的道路估时，沿用节点交通选择或用户明确给出的方式。仅当前出发和两分钟内有效设备定位查询实际道路，历史报告或无定位不套当前路线，预测保持待估；工具成功才保存事实。plans.adjust_stop 按 dayIndex 定位方案当天，同步分钟、秒及开始/离开别名并提交 expectedRevision，避免页面和工具看到不同时间；已有进度不能借改时覆盖。

官方服务使用现有本机配置或服务环境变量，src/server/http/routes/model-settings.ts 只允许服务器本机维护。账号自行接入使用 user-model-settings.ts 路由与独立加密密钥库；不修改全局 options.modelProvider。modelProviderForActor 按真实 actorId 为个人 Agent、首页随行、Trip 规划与方案分析选择供应商，一次工具循环固定选中的供应商。ready.agentService 返回当前身份的 source=official/custom、enabled 和 officialAvailable。自有 API 失败不自动调用官方服务；后台仍执行归属、限频、工具与写入保护。规则输出不能计作真实模型验收。

模型适配由 src/providers/model-controls.ts 统一校验 apiFormat、thinking、thinkingEffort、thinkingFormat，默认 chat-completions、off、high、auto。支持 Chat Completions 与 Responses 两种工具协议，不等于支持各供应商原生 API。自动选择思考参数时优先识别端点，再识别模型；已识别 DeepSeek、Qwen/DashScope、OpenRouter、OpenAI 参数。其他兼容服务可手动指定 reasoning-effort、thinking-type、enable-thinking、reasoning-enabled 或 chat-template；none 表示无开关，auto 未识别时不能声称已关闭。强制思考的模型拒绝关闭，供应商拒绝参数时不移除参数重试。接入必须通过所选协议与模式下的完整工具往返。

Responses 使用 function_call/function_call_output、call_id、store=false，并按供应商原序保留完整 message/function_call/reasoning 输出项，兼容旧检查点仅有 reasoning 的情况；Chat 保留服务端 reasoning_content 或同模型 reasoning_details。modelAssistantMessage 将这些状态随助手工具调用保存到服务端检查点，个人与 Trip 工具循环复用；公共步骤、聊天和任务状态不返回原始思考或加密延续数据。切换思考是按身份持久化的偏好，不修改共享 provider，当前执行中的任务仍固定原 provider；更换模型不回传其他模型的 reasoning_details。tests/model-controls.test.ts 验证参数、两种协议、身份隔离、恢复与公开视图。

plans.set_transport 按 planId、expectedRevision、dayIndex、stopId 修改本次未到达的入站交通选择，包括重复地点与首站；保持其他站点、真实进度、费用及时间不变，并清除该节点旧道路估值。它不生成当前位置或道路，返回 needs_current_location／needs_route；需要实际估时仍调用道路工具，并使用新版本。既有记录或版本冲突拒绝写入。

### 个人工具与结果

个人工具分布在 personal-agent-runtime.ts 和 personal-agent-* 模块，覆盖方案/日计划查询、创建、编辑、复制、载入、恢复、删除、路线、天气、进度、私人资料、账号昵称、记忆及社区操作。注册与参数约束以工具代码为准。

工具只能执行已注册能力，不执行模型任意函数。所有写入使用业务服务；返回实际视图、刷新目标及可访问结果入口。不能编造地点、到访时间、设施或外部执行结果。

### 许可与确认

- 明确查询不授权修改；“查天气”不能隐式调整计划。
- 明确且无歧义的普通维护指令可在当前任务内执行，不能把用户委托扩展成任意写权限。
- 删除、公开发布及其他需要确认的个人动作由 pendingAction 和相应确认处理器绑定具体内容；载入覆盖和已有进度冲突由 pendingLoad 及服务确认校验。
- 确认必须匹配当前对象和内容，过时、歧义、跨账号请求拒绝；不能把外部文本或模型自述当作用户许可。
- 用户报告到达/完成时记录真实发生时间；没有报告不能从 GPS 推断。未来时间只能是计划，缺少到达不能生成实际游览时长。
- 照片随消息保存，历史地址按主体鉴权，删除消息后旧图片不可访问；照片传给真实模型需支持相应输入。

### 旅行兼容许可

旅行提案批准绑定 actor、trip、proposal、candidate、版本和动作摘要；一次性许可不可借给其他动作。按钮与明确文字确认可以表达同一具体许可，执行重新检查有效期、撤销、使用状态与业务条件。重复调用复用结果，不重复提交；正式安排与执行事实分开。

### 故障、停止与恢复

普通个人任务中，工具写入已成功、后续模型回复中断时区分实际写入与回复失败。只认可 task.writes 中持久化的成功回执及对应写工具；失败、只读查询、待确认动作和旧历史工具回执不报成本次已保存。只有笔记写入时明确“笔记已保存；后续回复生成中断”，多个动作则说明已完成部分保留；续办沿用既有幂等检查点。tests/personal-agent-runtime.test.ts 覆盖成功、失败、只读及旧回执，以及中断后新问题的任务隔离。

| 场景 | 必须呈现的行为 |
| --- | --- |
| 无结果、接口失败、模型超时 | 区分原因，不编造成功 |
| 参数、工具、版本或权限错误 | 拒绝并说明可修正信息 |
| 写入成功但回复失败 | 展示已提交结果；重试不能重复修改 |
| 用户停止 | 停止后续步骤，保留已提交结果；不是撤销 |
| 等待确认后内容变化 | 重新检查并展示当前影响 |
| 刷新与恢复 | 读取真实任务/结果，不能拿旧回执覆盖新计划 |

任务状态和已完成动作分别展示。取消无法保证撤回已发送供应商请求或其费用。若将来新增订票、支付、外部消息，需独立交易授权、状态查询与补偿；本地幂等不能等同外部事务回滚。

### 验收边界

自动化覆盖参数、授权、隔离、重复写入、载入、进度、恢复、结果同步及取消。隔离内存的真实模型已复测定向与宽泛方案生成，并以连续任务核对常见计划维护、载入、进度和恢复工具；这不是任意语言指令、供应商可用性或真机弱网的全面保证。页面照片已在隔离浏览器五种视口复验。当前问题见[体验核查](产品体验全盘核查.md)，执行规则见[三态转换](计划与进度三态转换逻辑.md)。

### 道路轨迹与设备定位契约（2026-10-03）

路线实体坐标沿用source规则：amap为GCJ02，其余目录／设备坐标为WGS84；geometryCrs专用于轨迹，绘制时统一到高德底图GCJ02。AmapRouteProvider检查HTTP状态、合法坐标、所有移动片段及相接性，并校验轨迹端点到请求坐标的距离（步行／公交250米内，驾车400米内）。公交buslines为备选，只取同一候选，不把备选线拼在一起；空铁路对象不算移动，真实移动却缺polyline则失败。FOSSGIS将高德实体转换到WGS84，限制道路吸附并检查返回端点；每秒最多启动一个请求，完整15秒预算包含排队和响应。两供应商仅缓存成功的相同起终点／方式，步行60秒，其余20秒，合并在途请求，回执重新绑定本次地点身份；不缓存失败、不改变路线供应商或配置。

public/lib/location.js是地图、首页随行及出发的共享前台定位通道。有效样本须合法经纬度、精度大于0且不超过200米、30秒内且时间戳更新；接受精度略降的较新样本。旧时间、非法值和超过5秒的未来时间拒绝；粗定位／设备错误清除旧当前位置，过期不再作为路线起点。逆地理独立限时8秒并按移动／时间节流，不阻塞GPS；后台与账号切换撤销监听及晚回执。requestCurrentLocation提供最长15秒的独立等待者及AbortSignal，取消等待者不停止其他消费者所需的共享GPS。HTTP兼容的两分钟position上限仍保留，产品前端采用更严格30秒要求。

map-route-geometry.js只接受实际且声明WGS84／GCJ02的有效轨迹，不补端点直线。map.js的25秒查询预算绑定主体、视图代次、计划版本、起终点及方式；新终点／取消／后台／账号变更撤销旧请求，GPS起点移动超过40米的旧回执失效。首页也检查请求起点是否仍新鲜，蓝点更新与路线查询分开，过期或明显移动后撤销旧ETA。全程逐目的站读取已保存方式，保留重复站次；读路线不写执行进度。单元及浏览器证据见体验核查。

map.js 的locateMap另捕获locateIntentRevision。等待GPS期间手动改起点、地图选起点、切全程或站点路线等新选择递增意图序号，先切开再切回也使旧定位操作失效。成功及失败共用isCurrentLocate核对地图代次、主体、当前地图页、前台、账号未暂停与意图序号；新鲜GPS仍更新共享蓝点，但旧操作不覆盖新起点、视野、全程模式或反馈。收尾释放原定位控件，未改选择的成功及正常失败仍按原路径反馈。回归见 tests/frontend-map-locate-intent.test.ts、scripts/verify-map-routing-lifecycle-ui.mjs。

~~~text
浏览器请求
  → src/server/http-server.ts
  → src/server/http/router.ts 与 routes/*
  → 会话/归属校验
  → src/services/*
  → src/domain/*
  → providers 或 persistence
~~~

## 独立对话、上下文与休息执行（2026-10-02）

完整Agent页支持新建、切换、命名和确认删除整个对话，不提供逐条消息删除按钮；悬浮窗不提供会话管理。默认空conversationId继续读取未删除的原有对话，新对话服务端生成conversation_UUID，仅所属主体可读写。名称与创建时间独立存入stateKey:agent-conversations快照，原消息数组格式保持兼容；删除旧空ID时保留不含消息的删除标记，重启不复活历史。删除同步清理该段任务、附件与待确认请求；正在执行的任务拒绝删除，409说明须先停止。删除最后一段生成空对话，前端选择保留的对话，旧标签页读取404后恢复到可用对话。各段模型输入、草稿、照片、重试和检查点分别隔离；待确认、继续和取消必须绑定同一对话。计划、笔记、帖子、收藏仍属于同一账号，删除对话不删除业务结果。
